这是南部区域赛后的过渡版本，刚转向交叉工具链的纯SMC版本，现在其实已经不建议使用了，但是国赛因为电脑故障且前期工作没有做好，导致最终版本的狗腿底盘代码丢失了，后续国赛期间因为轮腿的联调工作紧张没时间去重新更新狗腿代码，所以只能把过渡版本作为给师弟的遗留代码，以下是代码的注意事项
1.此代码中leg文件中的三次二项式为狗腿在气弹簧作用下的多数据拟合式子，用作气弹簧的动态补偿前馈，具体拟合方法为将狗腿在静止状态下测出各个高度下的最小静态力矩，随后将数据再maltab中进行拟合，具体的方法可以询问ai，因为我电脑里的数据已经丢失了
2.此代码为PID和SMC算法转换的过渡版本，其实很不推荐使用，但是github上这个已经是最新上传的了我也没招了，区域赛的pid版本因为赛后改过一些结构鲁棒性也不太好，再加上狗腿这个赛季要退休了，所以我建议师弟如果想玩狗腿的话底盘的关节控制代码最好自己重新书写，下面我会给出我当时接手狗腿后遇到的问题和思路：
-----------------------------------------------------------------------------------------------------------------------------
1.狗腿在失能状态下底盘不是平衡的，他有一定倾斜角度（这个设计为主动悬挂减震，想法是好的，但其实对于算法来说很折磨），所以再常态模式下，电机是需要持续进行力矩输出来保持底盘达到平衡的，而且这个需要抬起的角度虽然比较小，但是基于气弹簧的存在，他抬起后的角度刚好位于气弹簧工作和不工作的过渡的角度，所以会出现静止状态下底盘平衡，但是一旦底盘开始运动后因为惯性和加速度，关节处会出现上下抖动
2.在国赛期间我与仲恺的步兵电控对于狗腿步兵进行了控制方面的交流，他们采用的控制方法为前馈与腿长pid控制（还有一些什么滤波什么预测补偿的，好像是人家队里传下来的没跟我细说），效果方面为可以做到可控的平稳上台阶，但是动作不连贯且有几率卡再台阶处，相比于我们的狗腿稳定性会高出很多，但是我们的上台阶速度和操作方便程度会高很多，所以我建议师弟可以做腿长pid加smc滑模刚性控制，再移动时基于力矩进行观测和动态前馈，做起来其实不太简单，看你有没有兴趣了，因为狗腿这赛季估计已经退休了，但是如果做的话大概率可以学到很多东西，这里我不推荐lqr以及现在所谓的强化学习，一点是建模难度高，二是其实学的不如传统这么深入（个人观点）
3.关于新的工具链为cmake+gcc+nijia+openocd的一套嵌入式工具链，ide选择vscode，调试工具选择ozone，这套工具链的好处是可以再linux里完美运行，且全程可以使用vscode的ai插件辅助代码与调试，但是抛弃了传统的图形化界面的一些配置，使用门槛可能不小，但是习惯后还是特别好用的，因为其实看开源看多一点后也会发现其实很多学校是没有mdk文件的，但是如果你使用cmake和gcc可以对任何开源的文件进行包装和打开，再着就是，linux下使用ai的辅助是很方便的，因为整个系统比较开源且框架很简单，在这个环境下ai的权限会更高，也更考验你对ai的使用和预防，因为搞不好你ai真可以把你linux搞崩的
4.最后祝师弟有所收获，然后对于步兵电控来说，我认为主动学习新的算法和工具是很重要的，因为步兵作为一个基础兵种，如果只是想保证他的基本功能是很简单的，难的是如何把他的各个功能都做到极致，把更多的算法和功能优化给你的步兵，平时多逛逛rm的开源论坛和群聊，会有不少收获的
